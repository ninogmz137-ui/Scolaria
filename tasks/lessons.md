[2026-03-29] | API key 401 in production showed cryptic error | Always include actionable next step in user-facing error messages (where to regenerate, what to update)
[2026-03-30] | process.env.EXPO_PUBLIC_* undefined in EAS builds because .env is gitignored | NEVER rely on .env for EAS builds. Use app.config.js to read env vars at build time and inject into Constants.expoConfig.extra. Create a single getEnv.ts helper.
[2026-03-30] | EAS Secrets marked "Sensitive" don't get inlined into JS bundle | EXPO_PUBLIC_ vars must be "Plain text" visibility in EAS, or better: use app.config.js extra pattern
[2026-03-30] | Spent 4 builds debugging env vars without understanding Expo's env injection | Before fixing env issues: understand the FULL chain (where var is defined → how it reaches Metro → how Metro inlines it). Don't just add more env sources — verify the pipeline.
[2026-04-02] | Android elevation > 0 draws grey outline even with borderWidth: 0 — took 4 builds to find | On Android, ALWAYS set elevation: 0 on card components. Use only background color contrast for visual separation. Elevation is only for floating UI (modals, tab bars).
[2026-04-02] | Fixed GlassCard but missed 15+ other components with hardcoded borderWidth/elevation | Before claiming a visual fix is done: grep the ENTIRE codebase for the property. Fix once, fix everywhere.
[2026-04-09] | UI changes not visible despite correct file edits — multiple Metro servers running (8081, 8082, 8083) serving stale bundles | Always kill ALL node processes before starting a new server. User was hitting an old server with the old bundle.
[2026-04-09] | AriaAvatar change had no effect — MessagerieScreen had its own inline gradient avatars for Aria type, completely independent of AriaAvatar.tsx | Before editing a component, grep files_with_matches for the visual pattern (gradient colors, icon style) to find ALL rendering sites — not just the obvious component.
[2026-04-09] | White icon on white background — forgot to add shadow/border when switching from gradient to white background | When replacing a colored background with white/glass, ALWAYS add a shadow + slightly colored border to ensure visibility against light backgrounds.
[2026-04-10] | Safe area padding buried in contentContainerStyle caused flicker on first render before insets were computed | Own the safe area at the topmost container (paddingTop: insets.top on root View). Children don't need to know about it.
[2026-04-10] | KeyboardAvoidingView behavior=undefined on Android means keyboard hides the input bar | Always use behavior='height' on Android (behavior='padding' on iOS). Never leave behavior=undefined.
[2026-04-10] | gap: 8 on absolute-positioned flex container caused icon overlap on some Android builds | Replace gap with explicit marginRight/marginLeft on the affected children. gap in absolute containers is unreliable on Android.
[2026-04-17] | 7 EAS builds wasted because documented Android lessons (elevation nesting, undefined KAV behavior, low glass opacity) were only applied to some files — not ALL call sites | When a lesson logs a documented Android pattern, `grep files_with_matches` for the pattern across `src/**` and fix every occurrence in one pass. Never claim "Android polish is done" without the codebase-wide sweep.
[2026-04-17] | Bottom-sheet modal with `height: '88%'` + `marginBottom` overflowed the top safe area (ReglagesScreen) | For bottom-sheet modals inside a safe-area-padded overlay, use `flex: 1` on the sheet so the parent's padding + the sheet's marginBottom naturally constrain its size. Percentage heights ignore siblings' margins.
[2026-04-17] | Splash `backgroundColor: '#FAFAF8'` didn't match the icon PNG's white background → visible seam / "ghost" on Android splash | Match splash `backgroundColor` exactly to the splash image's actual background color. For a white-bg icon, use '#FFFFFF'.
[2026-04-17] | Static `paddingBottom: getInputBarPaddingBottom(insets.bottom)` on composer UniversalInputBar reserved 72+inset px for the floating tab bar even when the keyboard was open on Android → input masked or pushed offscreen under `behavior='height'` KAV | When a composer sits above a floating tab bar, make its bottom padding dynamic via `Keyboard.addListener('keyboardDidShow'/'keyboardDidHide')`. Shrink to ~12px gap while open, restore full tab bar clearance on hide. Centralize in a hook (`useKeyboardInputPadding`) to avoid per-screen drift.
[2026-04-17] | Bottom sheet drag-to-close needed to stay compatible with existing reanimated `useSharedValue` translateY | Use `PanResponder` from RN core (no new lib) in a `useMemo`, write `translateY.value = Math.max(0, g.dy)` during `onPanResponderMove`, close if `g.dy > 100 || g.vy > 0.8` on release, otherwise `withTiming(0)`. Attach `{...panResponder.panHandlers}` to a dedicated `handleWrap` View above the sheet header so inner buttons remain tappable.
[2026-04-17] | Silent child-ID mismatch: `ActiveChildContext` used `demo-lea/demo-lucas/demo-emma` while `childContext.ts MOCK_CHILDREN` used `'1'/'2'/'3'` → `getChildContext(childId).find()` always fell through to `MOCK_CHILDREN[0]` (Léa), so Aria discussed Léa even when user selected Emma or Lucas. No runtime error. | When two data files describe the same entities (children, classes, etc.), the ID scheme MUST be identical across all of them. After adding a new entity source, `grep` the full set of IDs across `src/` to verify. `.find(...) ?? fallback[0]` patterns hide this bug — add a `console.warn` in the fallback branch during dev so the mismatch is visible. Defaults on function params (`childId = '1'`) must also match the canonical scheme.
[2026-04-18] | Android topbar round icon buttons (40×40, solid white bg) had no shadow because Agent A chose a hairline border over `elevation` (conservative memory of the 2026-04-02 grey-frame lesson). Buttons looked flat against the gradient header. | The 2026-04-02 rule (elevation draws a grey frame on Android) applies to *card* surfaces — wide, low-contrast, no `borderRadius > 20`. For small circular/pill floating buttons with a solid opaque background and no `borderWidth`, `elevation: 4` is safe and renders a clean native shadow. Keep `borderWidth: 0` and high-opacity background; skip any hairline border.
[2026-04-18] | Aria suggestion chips used `flexWrap: 'wrap'` + `width: '48%'` — the layout silently collapsed to a single row of crushed chips on Android Yoga, despite rendering correctly on web. | Never use `flexWrap: 'wrap'` + percentage child widths for horizontal chip lists on Android. Prefer a `<ScrollView horizontal showsHorizontalScrollIndicator={false}>` with explicit `minWidth` / `maxWidth` / `minHeight` per chip and `marginRight` spacing. The ScrollView guarantees chips stay at intrinsic size and scroll off-screen rather than compressing.
[2026-04-18] | In-drawer ScrollView set `paddingBottom: TAB_BAR_SCROLL_PADDING` (120px) — same value used by main screens to clear the floating tab bar. Inside a drawer the floating tab bar is not present, so the 120px padding pushed the last conversation items under the drawer's own search bar. | `TAB_BAR_SCROLL_PADDING` is only for ScrollViews behind the floating tab bar at root. Inside modals, drawers, sheets, or any surface that covers the tab bar, use a small intrinsic bottom padding (16–24px). Centralize the distinction: if the container is above the tab bar, no need to clear it.
[2026-04-18] | `gap: 4` inside a filter pill (Pressable with icon + label + chevron) rendered all three on separate lines on Android. | `gap` on `flexDirection: 'row'` has intermittent support on older Android / Yoga paths. Always replace with explicit `marginRight` on all but the last child. This extends the 2026-04-10 lesson from absolute containers to any row where child order matters visually.
[2026-04-18] | FAB rendered `<LinearGradient style={styles.fabGradient}>` but the style was never defined → `undefined` style prop → LinearGradient collapsed to zero size with no visual error at build time. | When a LinearGradient fills a flex parent (FAB inner, card header), it MUST have explicit `width` + `height` (or `width: '100%'`, `height: '100%'`) defined. Define a sibling `fabGradient` / `gradientInner` style at the same time as the FAB style — pair them in one commit, never split across agents. TypeScript won't catch the missing style because `styles.x` returns `undefined` at runtime.
[2026-04-18] | FloatingTabBar rendered on top of a modal screen (Réglages) and on top of in-screen sidebar drawer (Aria) — `<Modal>` and in-Stack `transparentModal` both render BELOW the tab bar because the tab bar is owned by the parent Tab.Navigator. | For screens that must cover the floating tab bar (full-screen modals, sidebars), add a route-based opt-out in `FloatingTabBar.tsx`: `const ROUTES_HIDE_TAB_BAR = new Set([...]); if (ROUTES_HIDE_TAB_BAR.has(nestedRouteName)) return null;`. Don't try to cover the tab bar structurally — you'll lose every time to the navigator's z-order.
